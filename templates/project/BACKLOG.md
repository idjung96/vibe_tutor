# 백로그 (에이전트 협업용)

에이전트들이 나중에 처리할 일과 참고 메모를 여기에 모은다.
이 파일은 메인 세션만 쓴다. subagent는 자기 출력에 "BACKLOG: 설명" 한 줄로
후보를 내고, 메인 세션이 아래에 옮겨 적는다.

## 할 일 (actionable)

상태는 세 가지다. **파일을 셋으로 쪼개지 않는다** — 단계를 하나씩 도므로 진행 중인 것은
원래 하나뿐이고(WIP=1), 완료분은 BACKLOG_DONE.md 로 빠진다. 줄에 상태를 적는다.

- 대기:  - [ ] B-번호 설명 · 출처:stageN/역할 · 우선순위:상/중/하
- 진행:  - [~] B-번호 설명 · 출처:stageN/역할 · 우선순위:상/중/하 · 진행:stageM
- 완료:  - [x] … → stageN 처리   → **단계 merge 때 BACKLOG_DONE.md 로 옮긴다**

`[~]` 는 7-0에서 lead가 이번 단계 초점으로 고른 항목에 메인 세션이 표시한다. 단계가 끝나면
`[x]` 로 바꾸고 아카이브로 옮긴다. 진행 표시가 둘 이상 남아 있으면 지난 단계의 표시를
안 지운 것이다.

`selfcheck.py --ledger-stats` 가 대기·진행·완료 수와 **오래 묵은 항목 수**를 센다.
실측 프로젝트에서 열린 항목 279개 중 139개가 20단계 넘게 묵어 있었다 — 쌓이는 것은
컬럼이 없어서가 아니라 **그루밍이 안 돌아서**다.

## 메모·주의 (참고 — 처리 대상 아님)
실행할 일이 아닌 주의사항·코멘트를 한 줄씩.
형식: - 설명 · 출처:stageN/역할     예) - auth 모듈은 동시성에 약함 · 출처:stage2/reviewer
같은 설명이 두 번 이상 쌓이면 반복 문제 신호다. 그래서 이미 고친 지적도 유형은 남긴다.

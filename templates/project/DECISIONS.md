# 결정 기록

**한 건은 짧게 쓴다(15줄 목표).** 여기 적는 것은 *결정*이지 *조사*가 아니다.

형식(아래 블록은 예시다 — 실제 절은 `##` 로 시작한다):

```
## [날짜] 단계N: 제목
- 등급: A | B | C
- 질문: 무엇을 정해야 했나 — 한 줄
- 선택: 한 줄
- 변경: AS-IS → TO-BE (기존 동작을 바꾼 결정일 때만. 신규면 생략)
- 이유: 한 줄
- 버린 대안: 무엇을, 왜 버렸나 (없으면 "없음")
- 되돌리기: 이 결정을 뒤집으려면 무엇이 드나 (모르면 "모름")
- 조사: #이슈번호 또는 dev-agent-team/evidence/<파일> (없으면 "없음")
```

계속 지켜야 하는 것이면 제목에 `[규칙]` 을 단다 — `## [규칙] 로그는 common/logger 만 쓴다`.
고정 절은 오래돼도 아카이브되지 않고 주입에서 접히지도 않는다.

## 여기에 적지 않는 것

**코드를 읽으면 알 수 있는 것은 적지 않는다.** 적는 순간부터 낡고, 낡은 문서는 거짓말을 한다.

- 구현이 어떻게 되어 있는지에 대한 설명 → 코드를 읽어라.
- `payment_screen.dart:431` 같은 **위치 증거** → 줄 번호는 움직인다. 꼭 가리켜야 하면
  커밋 해시로 가리킨다(그건 안 썩는다).
- 조사 과정·케이스별 추적 → 이슈나 `dev-agent-team/evidence/` 로 빼고 번호만 남긴다.
- "BACKLOG 4건이 이미 해결돼 있었다" 같은 **임시 상태** → 결정이 아니다. BACKLOG 로.

## 왜 짧아야 하나

이 파일은 critic·lead 가 단계마다 받는다. 실측된 프로젝트에서 208건 5421줄까지 자랐는데,
중앙값은 7줄이었고 **41줄이 넘는 26건(12%)이 전체의 63%**를 차지했다. 한 건이 1447줄이었다.
그 1447줄 중 결정은 앞 30줄이고 나머지는 조사 기록이었다.

항목 수가 문제가 아니라 **한 항목의 크기**가 문제다. `selfcheck.py --ledger-stats` 가
큰 절을 경고한다.

여기서 코드를 읽어도 절대 알 수 없는 것만 남긴다 — Owner 가 무엇을 골랐나, 무엇을 버렸나,
왜 버렸나, 되돌리는 데 무엇이 드나.
